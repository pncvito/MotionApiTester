## 第四轮：修用户实测反馈的三个界面问题

用户在 VS 里跑过之后反馈三条：① 点右上角放大会界面显示不全；② 软件图标没用上 app.ico；
③ 实时日志也显示不全。

### 1. 最大化被裁切（根因是窗口外壳，不是布局）
`WindowStyle=None` + `WindowChrome` 组合下，WindowChrome 在最大化时把窗口尺寸算成
「工作区 + 2×ResizeBorderThickness」，同时它让客户区等于整个窗口（`GlassFrameThickness=0`），
于是窗口物理上比工作区大 12px、溢出屏幕，**右侧与底部各被裁 6px**。

**修法**：`OnSourceInitialized` 里挂 `HwndSource` hook 接管 `WM_GETMINMAXINFO`——
用 `MonitorFromWindow(hwnd, MONITOR_DEFAULTTONEAREST)` + `GetMonitorInfo` 取 `rcWork`
（工作区，不是 `rcMonitor`，否则会盖住任务栏），把 `ptMaxSize` / `ptMaxPosition` 钉死。
因为这里设了 `handled = true`，会同时挡掉 WindowChrome 与 WPF `Window` 自己的处理，
所以**必须自行承担最小尺寸**：把 `ptMinTrackSize` 设为 `MinWidth/MinHeight`
（用 `CompositionTarget.TransformToDevice` 换算 DPI）。
另外在 `StateChanged` 里把 `ResizeBorderThickness` 在最大化时归零，作为双保险。
顺带加 `MinWidth="900" MinHeight="640"`（日志展开需要 233px，主内容 `MinHeight="180"`）。

**踩到的 API 坑**：`ResizeBorderThickness` / `CaptionHeight` 是 WindowChrome 的**实例属性**，
不是附加属性 —— **没有** `WindowChrome.SetResizeBorderThickness`（编译报 CS0117）。
取实例的正确方式：`WindowChrome.GetWindowChrome(window)`。

### 2. app.ico 没被用起来
`app.ico`（21KB，含 16/24/32/48/64/128/256 共 7 个尺寸）此前只配了 csproj 的 `<ApplicationIcon>`，
那只决定 exe 的**文件图标**。要让 WPF 用上必须另行登记为资源：
- csproj 加 `<Resource Include="app.ico" />`
- `Window` 加 `Icon="app.ico"`
- 标题栏左侧的纯色「M」方块换成 `<Image Source="app.ico" Width="20" Height="20"/>`

漏登记 Resource 会在启动时抛 `XamlParseException`（资源找不到）——
已用 Python 直接搜 `obj/Debug/MotionApiTester.g.resources` 确认 `app.ico` 条目已嵌入。

### 3. 实时日志显示不全
两层原因，都修了：
- **布局层（主因）**：主内容三栏那层用 `Grid.Row=2 RowSpan=3 Margin="0,28,0,23"` 覆盖 row2/3/4，
  把日志 Expander（row4）整个盖住；日志自己又 `Margin="0,0,0,22" RowSpan="2"` 叠在底栏上，
  展开后只剩个 Header 露在外面。
  **修法**：改为各行独立占位 —— 主内容 `Grid.Row=3`（弹性行）、日志 `Grid.Row=4`，
  去掉全部覆盖式 Margin/RowSpan；日志展开时真实挤压主内容高度，不再互相遮挡。
- **控件层**：TextBox 默认 `HorizontalScrollBarVisibility=Hidden`，长日志行被直接截断；
  且 `Text` 追加在末尾时视图不跟随滚动（WPF TextBox 保持原垂直偏移），新日志落在可视区外。
  **修法**：`HorizontalScrollBarVisibility="Auto"` + 新增 `TbLog_TextChanged` 处理器调用
  `ScrollToEnd()`，但只在「视口原本贴底」时才跟随，避免用户向上翻阅历史时被强行拉回。

### 编译校验通道的两个新坑（都浪费了一轮）
1. **与 VS 构建竞态**：`.verify` 要 glob `src/obj/Debug/*.g.cs`。用户恰在 VS 里构建时 g.cs 正被
   重写 → glob 读空 → 报 **53 个**「当前上下文中不存在名称 InitializeComponent」假错误。
   重跑一次即恢复 0 error，**不要据此改代码**。
2. **`x:Name` 与校验通道冲突**：XAML 新增 `x:Name` 会让 code-behind 依赖 g.cs 生成的字段，
   而 `.verify` 用的是 VS 上一次生成的 g.cs（无法现场重新生成 XAML）→ 在 VS 构建之前必然编译失败。
   所以窗口按钮、日志框都改成用 `sender` 拿控件，不新增 `x:Name`（`ResizeBorderThickness` 改用
   `WindowChrome.GetWindowChrome`）。将来若必须加 `x:Name`，加完要先在 VS 构建一次再跑校验。
