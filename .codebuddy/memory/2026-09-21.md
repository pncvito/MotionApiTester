# 2026-09-21

## 排查：EolSeriesBaseInterface.FixtureMoveToLoadUnloadingPosition 返回 (False, NRE)

日志现象：调用返回 `(False, 未将对象引用设置到对象的实例。)`，但工具打出「✅ 调用成功」；
同时夹着两条「✗ 依赖缺失 Prism.DryIoc.Wpf.dll / CustomCore.dll」，而 120ms 后的体检又写「11 个引用全部可解析」。

**结论：两条日志都是误导，API 返回 NRE 与依赖无关。**

1. `Prism.DryIoc.Wpf` / `CustomCore` 都在机型 DLL
   `OptoFidelity.BinocRainbowSyetemDisplayEolTester.dll` 的 Costura 资源里（读了 73 个 `costura.*` 资源名核实），
   磁盘上本来就不该有文件。AssemblyResolve 是多播事件，我们的处理器先返回 null 并**立刻**喊"缺失"，
   后面 Costura 的处理器随后就供出来了 → 自相矛盾。缺失报告必须延迟裁决。
2. `Microsoft.VisualStudio.DesignTools.WpfTap.resources.dll` 是 VS 调试器往进程里注入 WpfTap 后的卫星程序集探测，
   与设备无关，属环境噪声。
3. NRE 真因：实例未初始化。`BaseInterface` 的字段 `motionLogic` / `systemLogic` / `Bootstrapper` 都还是 null
   （无参构造出来的对象）。设备侧初始化入口是 `BaseInterface.InitializeFixture(Action<string> logger, string dutTypeRecipeName)`
   （public；同类的 `Init(...)` 是 internal，工具树里看不到）。

## 改动（3 处，均已 MSBuild 编译通过）

- `Services/ApiInvoker.cs`
  - 新增 `TryReadApiFailure` / `BuildApiFailureHint`：识别 `(bool, string)` 元组返回值约定，首项 false 即判失败，
    结果卡片转红、`InvokeResult.Success=false`，不再打「✅ 调用成功」；NRE 时补一句"实例未初始化"的提示。
  - 实例解析重构：新增 `FindReusable`（已建实例里取可赋值给声明类型的那个）+ `DerivationDepth`，
    `FindImplementation` 改为「派生得最深优先」。**这是关键**：`ReflectionEnumerator` 用 `DeclaredOnly`，
    成员分别挂在 `BaseInterface` / `EolSeriesBaseInterface` 节点下，旧逻辑按声明类型各建各的实例，
    导致 InitializeFixture 永远作用不到派生类的动作方法上。
  - 显式调用构造函数后把实例登记进 `_instanceCache`，后续实例方法复用它。
- `Services/DependencyResolver.cs`
  - 未命中改为 `QueueMiss` 挂起，400ms 后由 `FlushPendingMisses` 裁决：已加载进进程就记「已由其他解析途径供出」，
    否则才报缺失。避免与体检结论打架。

待用户在真实设备上验证：先 `InitializeFixture` 再调动作方法。
